# Hinana Studio Novel

같은 글을 여러 기기에서 비교해 읽을 수 있도록 만드는 **Electron 데스크톱 프로그램**입니다. `/Users/hinana/HinanaStudioArcade`를 참고해 Electron + React + TypeScript + Vite 구성을 참고했습니다. 화면은 원고 작성·독서 미리보기·환경 비교의 세 단계로 구성하며, 남색 라이브러리와 밝은 원고 면을 사용합니다.

## 실행

Node.js 24 이상을 권장합니다.

```sh
npm ci
npm run dev
```

빌드 후 데스크톱 앱을 실행하려면:

```sh
npm run build
npm start
```

`npm run pack`은 `release/`에 로컬 실행용 앱 번들을, `npm run dist`는 현재 운영체제용 배포물을 만듭니다. macOS 빌드는 코드 서명하지 않은 로컬 테스트용입니다. Windows 패키지는 Windows 환경에서 빌드하는 것을 권장합니다.

## 사용 흐름

1. 작품명과 지은이를 입력하고, 글 목록에 글을 추가합니다.
2. 원고를 쓰거나 붙여 넣습니다. UTF-8 `.txt`, `.md` 파일을 여러 개 가져올 수도 있습니다. Markdown은 일반 텍스트로 취급합니다.
3. 글꼴·크기·줄 간격·자간·여백·정렬·들여쓰기·배경색과 가로쓰기/세로쓰기를 설정합니다.
4. **환경 비교**에서 작은 태블릿, 큰 태블릿, 스마트폰, 데스크톱의 화면 크기 프리셋을 나란히 비교합니다. 기기의 화면 방향은 글 방향과 따로 전환합니다.
5. **저장**으로 `.hinananovel` 파일에 글과 독서 설정을 보관합니다.
6. **웹으로 내보내기**에서 모든 글과 목차, 설정을 단일 `.html` 파일로 만듭니다. 파일을 다른 기기로 옮겨 브라우저에서 열거나 정적 HTTP 서버에 올립니다. 서버의 첫 화면으로 쓰려면 `index.html`로 배치합니다.

앱에서 서버에 자동 업로드하지 않으며, Sites 생성이나 배포를 실행하지 않습니다. HTML은 외부 CDN, 스크립트, 서버 API에 의존하지 않습니다. 가로쓰기는 세로 스크롤, 세로쓰기는 오른쪽에서 왼쪽으로 진행하는 가로 스크롤을 사용합니다.

## 같은 조건으로 비교하기

프리셋은 CSS 픽셀 기준의 화면 크기 예시입니다. 기기 실물이나 특정 모델의 정확한 에뮬레이터가 아닙니다. 같은 HTML을 실제 기기에서 열어 최종 확인하세요. 미리보기는 작업 영역에 맞춰 축소 표시하며, 내보낸 HTML은 실제 브라우저 화면에 맞춰 표시합니다. 좁은 가로쓰기 화면에서는 여백을 24px로 조정합니다.

명조/고딕/고정폭 기본 옵션은 운영체제의 글꼴을 사용하므로 기기마다 글 모양과 줄바꿈이 달라질 수 있습니다. **글꼴 파일 포함하기**로 WOFF2/WOFF/TTF/OTF를 가져오면 프로젝트와 HTML에 글꼴 데이터를 포함해 같은 글꼴을 전달합니다. 글꼴의 웹 임베딩 허용 여부는 해당 라이선스로 확인하세요. 실제 렌더링, 화면 밝기와 색은 브라우저·운영체제·패널에 따라 달라질 수 있습니다.

## 저장과 복구

- 프로젝트 파일: `.hinananovel` JSON, 현재 형식 버전 1.
- 마지막 작업 한 개를 Electron의 userData 폴더에 0.7초 지연으로 자동 기록합니다. 앱을 다시 실행하면 복구하며, 복구한 작품은 저장 경로를 다시 선택합니다.
- 자동 복구 실패는 하단에 표시합니다. 자동 복구를 파일 백업 대신 사용하지 마시고 프로젝트 파일을 따로 저장하세요.
- 프로젝트 최대 28MB, 글 최대 500개, 글 하나당 최대 200만 자입니다. 가져올 텍스트 파일은 UTF-8 2MB 이하, 글꼴 파일은 10MB 이하입니다.
- 열기·새 작품·종료 시 저장하지 않은 변경 사항을 확인합니다. 잘못된 프로젝트를 열어도 기존 원고와 저장 경로를 유지합니다.
- ⌘/Ctrl+N 새 작품, O 열기, S 저장, Shift+S 다른 이름으로 저장, E 웹 내보내기. 원고 편집은 기본 텍스트 편집의 실행 취소/다시 실행을 사용합니다.

## 검증

```sh
npm test
npm run build
npm run test:ui
```

단위 테스트는 프로젝트 검증, 글 순서·문단 유지, HTML 이스케이프, 글꼴 포함과 세로쓰기를 검사합니다. UI 검증은 임시 사용자 데이터 폴더로 실제 Electron을 실행하여 편집·텍스트 가져오기·순서 변경·저장·다시 열기·취소·웹 내보내기·재시작 복구를 확인하고, 독립 HTML을 세 가지 화면 크기로 검사합니다. 결과 화면은 `test-results/`에 저장합니다.

## 구조

- `electron/main.cjs`, `preload.cjs`: 네이티브 대화상자, 파일 입출력, 자동 복구와 제한된 IPC.
- `src/`: React 편집기와 화면 크기별 iframe 미리보기.
- `shared/core.mjs`: 프로젝트 검증과 독서 HTML 생성. 미리보기와 실제 내보내기가 공유합니다.
- `tests/`, `scripts/smoke.mjs`: 데이터·내보내기 단위 테스트와 Electron 통합 검증.

렌더러의 Node.js 접근을 끄고 context isolation과 sandbox를 켰습니다. 원고를 HTML 텍스트로 이스케이프하며, 독서 HTML은 CSP 해시가 일치하는 고정 독서 코드만 실행하며, 원고를 코드로 실행하지 않습니다.

로컬 macOS 앱 번들을 만든 뒤에는 `node scripts/smoke-package.mjs`로 패키징된 앱의 실행·저장·내보내기와 종료 전 저장 처리를 검증할 수 있습니다. 다른 실행 파일을 검사하려면 인자로 절대 경로를 전달하세요. `npm run icons`는 사용자가 제공한 원본 `public/novel-icon-source.png`에서 앱 아이콘을 다시 생성합니다. 프로그램 정보는 작업 화면 왼쪽 아래와 운영체제의 앱 정보 메뉴에서 열 수 있습니다.

## hinana.moe 작품 일람 연동

**웹으로 내보내기 → hinana.moe → 외부 브라우저에서 게시**를 누릅니다. 기본 브라우저에서 평소 사용하는 사이트 계정으로 로그인하고 작품명·작가·분량을 확인한 뒤 **확인하고 게시**를 누르세요. 완료 결과는 자동으로 Novel에 표시됩니다. 게시는 비나래 계정에 한정합니다.

앱 안의 로그인창·계정 조회·직접 서버 전송은 사용하지 않습니다. 브라우저의 쿠키를 앱으로 복사하지 않습니다. 웹에 프로젝트 파일을 고르는 업로드 폼도 제공하지 않습니다. 원고는 브라우저에서 승인한 후에만 로컬 앱으로부터 전달하며, 승인은 해당 원고의 해시와 메타데이터에 묶여 한 번만 사용할 수 있습니다.

승인된 원고는 `/hinana/works`에 공개됩니다. 같은 프로젝트를 다시 게시하면 기존 주소에서 원고·글꼴·독서 설정을 갱신합니다. 소개는 프로젝트에 저장됩니다. 다른 이름으로 저장한 사본은 같은 작품 식별자를 유지하므로 별도 작품을 만들려면 ‘새 작품’을 사용하세요.

앱은 게시할 때만 `127.0.0.1`의 임의 포트와 무작위 반환 경로를 열어 브라우저에 원고를 전달하고 결과를 받습니다. 로그인과 게시 승인은 외부 브라우저에서 진행합니다. 승인 유효시간은 5분, 앱 대기는 10분이며 **브라우저 다시 열기**와 **게시 취소**를 제공합니다. 완료·취소·만료 시 임시 수신기를 닫습니다. 브라우저가 닫혀도 새 게시를 시작하기 전에 대기 중 작업을 취소할 수 있습니다.

새 앱과 `/Users/hinana/hinana.moe` 서버 변경을 함께 배포해야 합니다. 이미 걸린 IP 단위 임시 차단은 브라우저 전환으로 해제되지 않으므로 차단 만료 또는 사이트의 기존 관리 기능에서 해제 후 사용하세요. 자동 계정 조회와 반복 재시도는 하지 않습니다.

개발 서버는 `HINANA_NOVEL_SERVER=http://127.0.0.1:<포트>`로 지정합니다. 운영 주소는 `https://hinana.moe`입니다. `node scripts/sync-hinana-reader.mjs --check`는 렌더러의 일치 여부를 검사합니다. `node scripts/smoke-hinana.mjs`는 별도 Chromium 브라우저를 사용한 전체 연동을 로컬에서 검증합니다. `--packaged`로 macOS 패키지를 검증할 수 있습니다.


## 책처럼 읽기

독서 설정의 **읽기 방식 → 책처럼 읽기**를 선택하면 전자책처럼 페이지를 넘겨 읽습니다. **화면에 맞춰 자동 / 한 쪽 / 두 쪽 보기**를 고를 수 있으며, 자동 모드는 넓은 화면에서 두 쪽을 펼칩니다. 좁은 화면은 한 쪽을 사용합니다. 기존 프로젝트는 스크롤 모드를 유지합니다.

- 미리보기·단일 HTML·hinana.moe 독서 화면에서 같은 페이지 나누기 코드를 사용합니다. 기존 게시 작품도 서버 업데이트 후 독서 화면의 ‘책처럼 읽기’로 전환할 수 있습니다. 예전에 내보낸 HTML은 다시 내보내 주세요.
- 이전/다음 버튼, 화면 가장자리 클릭, 좌우 스와이프, 좌우 방향키, Page Up/Down·Space로 넘깁니다. Home/End는 처음/끝으로 이동합니다. 세로쓰기는 오른쪽에서 왼쪽으로 읽으며 넘김 방향도 이에 맞춥니다.
- 목차로 장을 고르고, 페이지 번호와 진행률을 확인합니다. 페이지 수는 글꼴과 화면 크기에 따라 달라집니다. 화면을 회전하거나 크기를 바꾸면 읽던 위치를 기준으로 다시 나눕니다.
- 독립 HTML과 hinana.moe는 브라우저 저장소가 허용될 때 읽던 위치를 기억합니다. 편집기 미리보기는 기기 비교를 위해 매번 선택한 글의 처음에서 시작합니다. 방문 기록 삭제·시크릿 모드·다른 브라우저 사이에서는 위치가 공유되지 않습니다.
- 원고를 이스케이프한 뒤 DOM 텍스트로 페이지를 만들며, 고정 독서 코드만 CSP SHA-256 해시로 실행을 허용합니다. 앱과 사이트의 미리보기 iframe은 사이트 원본 권한을 부여하지 않습니다.

독서 코드를 바꾸면 `node scripts/update-reader-hash.mjs` 후 `node scripts/sync-hinana-reader.mjs`를 실행하세요. `node scripts/smoke-reader.mjs`로 글 누락·페이지 잘림·방향 전환·이어 읽기와 CSP/iframe 격리를 검증합니다.
